Haskell Revision Notes

1.1 So what's Haskell?

  • Purely functional: you tell Haskell what things are, not the steps to follow. Once a is 5, it stays 5.
  • Lazy: it only computes a result when you actually need it.
  • Statically typed: the compiler checks types before the program runs.
From lecture notes (Lecture 1): pure and impure
  • Pure function: result depends only on its arguments, and it does nothing else (no mutation, no I/O, no hidden state). Same input gives same output; easy to test, reason about, compose. Example: square x = x * x.
  • Impure (has effects): reads or changes the world: printing, files, the clock, randomness. Order and timing now matter.
  • Discipline: keep as much of a program pure as possible, push effects to the edges.
From lecture notes (Lecture 1): what this asks of the language
  • A type system that names effects: putStrLn :: String -> IO ()
  • Recursion in place of loops. Pattern matching to drive control flow.
length [] = 0
length (x:xs) = 1 + length xs
describe :: [a] -> String
describe []     = "empty"
describe [x]    = "a single element"
describe (x:xs) = "several elements"
DoKeep functions pure; ask "same input, same output?".
Don'tThink of Haskell as "step 1, step 2" with variables that change.

Q1 · EasyWhich are pure: square x = x*x, getLine, length [1,2,3], reading the clock?
Solution A

Pure: square, length. Impure: getLine, the clock.

Why: test "same input always gives same output?"

Solution B

Same answer, using types: impure things show up as IO (getLine :: IO String); square and length have no IO.

Q2 · EasyWrite describe :: [a] -> String: "empty", "one", or "many".
Solution A
describe []  = "empty"
describe [_] = "one"
describe _   = "many"

Why: pattern matching picks the case by the list's shape.

Solution B
describe xs = if null xs then "empty"
              else if length xs == 1 then "one" else "many"

Why: same result with if; longer, so patterns are preferred.

Q3 · MediumWrite your own length' for lists.
Solution A
length' []     = 0
length' (_:xs) = 1 + length' xs

Why: recursion replaces the loop: empty list is 0, otherwise 1 plus the rest.

Solution B
length' xs = sum [1 | _ <- xs]

Why: turn every element into 1, then add.

Q4 · MediumWrite sumTo n: 1 + 2 + ... + n (n at least 0).
Solution A
sumTo 0 = 0
sumTo n = n + sumTo (n - 1)

Why: base case 0, then shrink n by one each call.

Solution B
sumTo n = sum [1..n]

Why: a range plus sum; shortest.

Solution C
sumTo n = n * (n + 1) `div` 2

Why: maths formula, no looping at all.

Q5 · HardWrite myReverse without using reverse.
Solution A
myReverse []     = []
myReverse (x:xs) = myReverse xs ++ [x]

Why: reverse the tail, put the head at the end. Simple but slow on long lists (++ walks the left list).

Solution B
myReverse xs = go xs []
  where go []     acc = acc
        go (y:ys) acc = go ys (y:acc)

Why: : at the front is instant, so build the answer in acc. Faster.

2.2 Calling functions

  • Name, space, arguments: succ 8, min 9 10. No brackets or commas.
  • Function application binds tightest: succ 9 + max 5 4 + 1 = 16.
  • Infix with backticks: 92 `div` 10 = 9. bar (bar 3) = bar of (bar 3).

Don'tsucc 9 * 10 is (succ 9) * 10 = 100.

2.5 Ranges

2.7 Tuples

  • Fixed size, mixed types allowed. Each size is its own type: [(1,2),(8,11,5)] is an error. No one-element tuple.
  • fst, snd: pairs only. zip pairs two lists; longer is cut off; zip [1..] xs works.
[(a,b,c) | c <- [1..10], a <- [1..c], b <- [1..a],
           a^2 + b^2 == c^2, a+b+c == 24]   -- [(8,6,10)]
DoTuple when the size is known; list when it varies.
Don'tUse fst/snd on triples.
From lecture notes (Lecture 1): worked example, Conway's Game of Life
  • Infinite grid; each cell live or dead with 8 neighbours; all update at once. Birth: dead cell with exactly 3 live neighbours becomes live. Survival: live cell with 2 or 3 stays live. Death: all others (under 2 isolation, over 3 overcrowding).
  • Glider seed drifts one square up-and-right every four generations. Other seeds vanish, stabilise or oscillate. Life is Turing complete.
  • Store only live cells: sparse and unbounded. No arrays, no bounds, no mutation.
type Cell = (Int, Int)
type Grid = [Cell]
glider :: Grid
glider = [(1,3),(2,1),(2,3),(3,2),(3,3)]
isLive, isDead :: Cell -> Grid -> Bool
isLive c g = c `elem` g
isDead c g = not (isLive c g)
neighbours :: Cell -> [Cell]
neighbours (x,y) = [(x+i,y+j) | i <- [-1..1], j <- [-1..1], not (i==0 && j==0)]
liveNeighbours :: Grid -> Cell -> [Cell]
liveNeighbours g c = [c' | c' <- neighbours c, isLive c' g]
step :: Grid -> Grid
step [] = []
step g =
  [ (x,y) | x <- [minX-1..maxX+1], y <- [minY-1..maxY+1]
  , (isDead (x,y) g && length (liveNeighbours g (x,y)) == 3)
    || (isLive (x,y) g && length (liveNeighbours g (x,y)) `elem` [2,3]) ]
  where minX = minimum [x | (x,_) <- g] ; maxX = maximum [x | (x,_) <- g]
        minY = minimum [y | (_,y) <- g] ; maxY = maximum [y | (_,y) <- g]

step builds a new generation; the old grid is never changed. Run the game by iterating: step g, step (step g), ...

Solution A
triples p = [(a,b,c) | c <- [1..p], a <- [1..c], b <- [1..a],
                       a^2 + b^2 == c^2, a+b+c == p]

triples p = [(a,b,c) | a <- [1..p], b <- [1..a], let c = p - a - b,

Why: the perimeter fixes c, so one loop goes away.

3.1 Believe the type

  • Static type system: the type of every expression is known at compile time, so errors (like dividing a boolean by a number) are caught before running. Everything has a type.
  • Type inference: you needn't write types for numbers etc.; Haskell works them out. A type is a label saying which category an expression fits.
  • :t expr in GHCi shows the type. :: is read "has type of". Types start with a capital letter.
  • Each tuple length has its own type. Functions have types too; declaring them is good practice (except very short functions).
  • [Char] is the same as String. Parameters and result are all separated by ->; the last item is the return type.
  • Unsure of a type? Write the function without it, then check with :t.

ghci> :t (True, 'a')  (True, 'a') :: (Bool, Char)

3.2 Type variables

  • :t head gives [a] -> a. a is lowercase, so it is a type variable: any type (like generics, but more powerful). Functions using them are polymorphic. Usually named a, b, c, d.
  • fst :: (a, b) -> a. Different variables a, b don't have to be different types; it just says result type = first component's type.
DoUse type variables for functions that don't depend on specific types.

3.3 Typeclasses 101

  • A typeclass is like a Java interface (but better; not like OOP classes): it defines behaviour; a type in the class implements it.
  • (==) :: (Eq a) => a -> a -> Bool. Operators are functions: wrap them in brackets to see the type or call them prefix. Before => is the class constraint: both values have the same type, and it must be in Eq.
  • elem :: (Eq a) => a -> [a] -> Bool because it uses ==.

Tracking constraints (result sorts a list of type [(Int, a)]):

A new type starts with no instances: Red == Blue gives "No instance for Eq Party", and GHCi can't even print a value. So GHC writes them for us:

  deriving (Eq, Ord, Show, Enum, Bounded)

4.1 Pattern matching

  • Give separate bodies for different patterns (numbers, chars, lists, tuples...). Checked top to bottom; first match wins. Put specific patterns first, catch-all last.
  • No catch-all means a runtime error: "Non-exhaustive patterns".
lucky :: (Integral a) => a -> String
lucky 7 = "LUCKY NUMBER SEVEN!"
lucky x = "Sorry, you're out of luck, pal!"
factorial :: (Integral a) => a -> a
factorial 0 = 1
factorial n = n * factorial (n - 1)
charName 'a' = "Albert"      -- charName 'h' crashes: no catch-all
  • Tuples: addVectors (x1, y1) (x2, y2) = (x1 + x2, y1 + y2). Triples: first (x, _, _) = x. _ = don't care.
  • Also inside comprehensions: [a+b | (a,b) <- xs]; a failed match just skips that element.
  • Lists: [], x:xs (length 1 or more), x:y:z:zs (3 or more). Use brackets around : patterns. x:[] = [x], x:y:[] = [x,y]; x:y:_ can't be square brackets.
  • error "msg" crashes with a message; use sparingly.
head' :: [a] -> a
head' [] = error "Can't call head on an empty list, dummy!"
head' (x:_) = x
length' :: (Num b) => [a] -> b
length' [] = 0
length' (_:xs) = 1 + length' xs
sum' [] = 0
sum' (x:xs) = x + sum' xs
capital all@(x:xs) = "The first letter of " ++ all ++ " is " ++ [x]   -- as-pattern
  • length' on "ham": 1 + (1 + (1 + 0)). The empty list is the edge condition.
  • As pattern name@pattern: break up and keep the whole. You can't use ++ in patterns.
From lecture notes (Lecture 1): pattern matching and recursion

Pattern matching drives control flow; recursion replaces loops:

describe :: [a] -> String
describe []     = "empty"
describe [x]    = "a single element"
describe (x:xs) = "several elements"
DoAlways include a catch-all. Put the edge condition first. Prefer patterns to fst/snd.
Don'tPut the catch-all on top (it hides the rest; factorial would never stop). Don't use ++ in a pattern.

4.2 Guards, guards!

  • Patterns check the shape; guards check a true/false condition. Like a readable if-else tree. Written with |, indented; first True wins; otherwise = True catches all.
  • If every guard is False, evaluation falls to the next pattern; if none match, error.
  • No = after the name and parameters, before the first guard. Inline guards work but are hard to read. You can define functions with backticks: a `myCompare` b.
densityTell :: (RealFloat a) => a -> String
densityTell density
    | density < 1.2     = "Wow! You're going for a ride in the sky!"
    | density <= 1000.0 = "Have fun swimming, but watch out for sharks!"
    | otherwise         = "If it's sink or swim, you're going to sink."
max' :: (Ord a) => a -> a -> a
max' a b
    | a > b     = a
    | otherwise = b
myCompare :: (Ord a) => a -> a -> Ordering
a `myCompare` b
    | a > b     = GT
    | a == b    = EQ
    | otherwise = LT
DoEnd with otherwise. Line up the pipes.
Don'tPut = before the first guard. Don't write guards on one line.

4.3 Where!?

  • Bind names once after the guards, visible across all guards of that function only; avoids repetition, improves readability, computed once. Align names in one column.
  • Not shared across different patterns of one function (use a global for that). Can pattern match, define functions, and be nested.
densityTell mass volume
    | density < air   = "Wow! You're going for a ride in the sky!"
    | density <= water = "Have fun swimming, but watch out for sharks!"
    | otherwise        = "If it's sink or swim, you're going to sink."
    where density = mass / volume
          (air, water) = (1.2, 1000.0)
initials firstname lastname = [f] ++ ". " ++ [l] ++ "."
    where (f:_) = firstname
          (l:_) = lastname
calcDensities xs = [density m v | (m, v) <- xs]
    where density mass volume = mass / volume
DoName repeated expressions in where. Align the names.
Don'tExpect a where name to be visible in another pattern's body.

4.4 Let it be

  • let <bindings> in <expression>. Bindings come first; let is an expression (usable anywhere) but local: doesn't span guards. where is just syntax, covers the whole function incl. guards.
  • Separate inline bindings with semicolons; let can pattern match; can define local functions.
  • In a comprehension, let (no in) binds names without filtering; visible to later parts and the output, not earlier ones. In GHCi, let is optional now.
cylinder :: (RealFloat a) => a -> a -> a
cylinder r h =
    let sideArea = 2 * pi * r * h
        topArea = pi * r ^2
    in  sideArea + 2 * topArea
ghci> 4 * (let a = 9 in a + 1) + 2          42
ghci> (let (a,b,c) = (1,2,3) in a+b+c) * 100   600
calcDensities xs = [density | (m, v) <- xs, let density = m / v, density < 1.2]
DoUse let inside an expression; where when guards share a name.
Don'tUse a let name across guards or before its binding in a comprehension.

4.5 Case expressions

  • Case is an expression: case expression of pattern -> result ...; first matching pattern wins; no match = runtime error. Parameter pattern matching is sugar for case. Unlike parameter patterns, case works anywhere in an expression.
head' xs = case xs of [] -> error "No head for empty lists!"
                      (x:_) -> x
describeList xs = "The list is " ++ case xs of [] -> "empty."
                                               [x] -> "a singleton list."
                                               xs -> "a longer list."
describeList xs = "The list is " ++ what xs   -- same, with where
    where what [] = "empty."
          what [x] = "a singleton list."
          what xs = "a longer list."
DoUse case to match in the middle of an expression.
Don'tForget the catch-all pattern.
Pay attention: try each solution on edge cases (0, empty list, ties).

Solution A

5.1 Hello recursion!

  • Recursion = a function applied inside its own definition. Common in maths: Fibonacci F(0)=0, F(1)=1, F(n)=F(n-1)+F(n-2).
  • The non-recursive parts (F(0), F(1)) are the edge condition. Without them it never stops (F(-2000) = F(-2001) + F(-2002)...).
  • Haskell computes by declaring what something is, not how to get it. So there are no while/for loops: use recursion.
From lecture notes (Lecture 1: recursion in place of loops)
length [] = 0
length (x:xs) = 1 + length xs
DoAlways write the edge condition first.
Don'tWrite a recursive case with no edge condition (it never ends).

5.2 Maximum awesome

  • Imperative way: keep a "max so far" variable and loop. Recursive way: the maximum of a singleton is its element; otherwise the bigger of the head and the maximum of the tail.
  • Pattern matching handles the edge conditions neatly. Splitting a list into head and tail (x:xs) is the common idiom.
  • Trace on [2,5,1]: 2 vs max [5,1]; 5 vs max [1]; max [1] = 1, so 5, so 5.
maximum' :: (Ord a) => [a] -> a
maximum' [] = error "maximum of empty list"
maximum' [x] = x
maximum' (x:xs)
    | x > maxTail = x
    | otherwise = maxTail
    where maxTail = maximum' xs
-- clearer, using max:
maximum' (x:xs) = max x (maximum' xs)
DoUse max x (maximum' xs): shorter than guards plus where.
Don'tForget the [] case: maximum [] has no answer, so crash with error.

5.3 A few more recursive functions

  • replicate': edge case is 0 or less. Guards, not patterns, because we test a condition. Needs (Num i, Ord i): Num is not a subclass of Ord (e.g. complex numbers have no order).
  • take': two edge cases (n <= 0, or empty list). A guard without otherwise falls through to the next pattern.
  • reverse': reversed tail, then the head at the end.
  • repeat': no edge condition, so it builds an infinite list; cut it with take 5 (repeat 3).
  • zip': two edge conditions (either list empty). elem': empty list gives False; else compare head, then check tail.
replicate' :: (Num i, Ord i) => i -> a -> [a]
replicate' n x
    | n <= 0    = []
    | otherwise = x:replicate' (n-1) x
take' :: (Num i, Ord i) => i -> [a] -> [a]
take' n _
    | n <= 0   = []
take' _ []     = []
take' n (x:xs) = x : take' (n-1) xs
reverse' :: [a] -> [a]
reverse' [] = []
reverse' (x:xs) = reverse' xs ++ [x]
repeat' :: a -> [a]
repeat' x = x:repeat' x
zip' :: [a] -> [b] -> [(a,b)]
zip' _ [] = []
zip' [] _ = []
zip' (x:xs) (y:ys) = (x,y):zip' xs ys
elem' :: (Eq a) => a -> [a] -> Bool
elem' a [] = False
elem' a (x:xs)
    | a == x    = True
    | otherwise = a `elem'` xs
DoUse guards for conditions (n <= 0), patterns for shapes ([], x:xs). Trace small examples on paper.
Don'tPrint an infinite list unsliced. Forget one of two edge conditions in two-list functions.

5.4 Quick, sort!

  • Quicksort: a sorted list = sorted smaller-or-equal values, then the head (the pivot), then sorted bigger values. Sorted twice, so two recursive calls. Edge: empty list.
  • Comprehensions filter the smaller and bigger parts. Any element could be the pivot; the head is easy to get by pattern matching.
quicksort :: (Ord a) => [a] -> [a]
quicksort [] = []
quicksort (x:xs) =
    let smallerSorted = quicksort [a | a <- xs, a <= x]
        biggerSorted = quicksort [a | a <- xs, a > x]
    in  smallerSorted ++ [x] ++ biggerSorted
-- quicksort [10,2,5,3,1,6,7,4,2,3,4,8,9] = [1,2,2,3,3,4,4,5,6,7,8,9,10]
-- [5,1,9,4,6,7,3] becomes [1,4,3] ++ [5] ++ [9,6,7], then each part is sorted
DoKeep equal values on one side (<=) so duplicates are not lost.
Don'tUse < on both sides: equal values would vanish.

5.5 Thinking recursively

  • Pattern: define an edge case, then combine one element with the function applied to the rest. Sum = head + sum of tail; product = head * product of tail; length = 1 + length of tail.
  • Edge case = where recursion makes no sense: list: []; tree: node with no children; numbers: often 0 (factorial).
  • Edge values are often an identity: 1 for multiplication, 0 for addition, [] for list joining.
  • Recipe: find the edge case, think about identities, decide how to split the parameters (list = head and tail), then choose where to recurse.

6.1 Curried functions

  • Every function really takes one parameter. max 4 5 is (max 4) 5: max 4 returns a function that takes the second number. So a -> a -> a means a -> (a -> a) (arrows associate to the right).
  • Calling with too few parameters gives a partially applied function: a handy way to make functions on the fly.
  • compareWithHundred = compare 100 (the x is dropped on both sides). multThree 9 gives a function needing two more numbers.
  • Sections: partially apply an infix operator with brackets: (/10), (elem ['A'..'Z']). Special case: (-4) is minus four; use (subtract 4).
  • multThree 3 4 in GHCi errors: a function has no Show instance, so it can't be printed.

6.3 Maps and filters

  • map f xs applies f to every element. filter p xs keeps elements where predicate p is True. Either can be written as a list comprehension: pick the more readable one. Several comprehension predicates = filter several times or join with &&.
  • Laziness: map and filter an infinite list and it still makes just one pass; takeWhile p xs takes elements while p holds.
  • Pattern: make a function, map it over values, filter the results (replaces nested loops).
map :: (a -> b) -> [a] -> [b]
map _ [] = []
map f (x:xs) = f x : map f xs
filter :: (a -> Bool) -> [a] -> [a]
filter _ [] = []
filter p (x:xs)
    | p x       = x : filter p xs
    | otherwise = filter p xs
quicksort (x:xs) = quicksort (filter (<=x) xs) ++ [x] ++ quicksort (filter (>x) xs)
largestDivisible = head (filter p [100000,99999..])
    where p x = x `mod` 3829 == 0

        | odd n  = n : chain (n*3 + 1)

Don'tUse filter to cut an infinite list: it never finishes.

  • Anonymous functions: \x y -> body, usually in brackets (otherwise they extend right). They are expressions. Can pattern match, but only one pattern per parameter; a failed match is a runtime error.

  • addThree = \x -> \y -> \z -> x + y + z shows currying (a gimmick). flip' f = \x y -> f y x makes it clear the result is meant to be passed on.

6.5 Only folds and horses

  • A fold reduces a list to one value using a binary function, a starting value (accumulator) and the list. Result type = accumulator type. Empty list gives the starting value.
  • foldl: from the left; function is \acc x -> .... foldr: from the right; function is \x acc -> ....
  • Rewrite foo a = bar b a as foo = bar b (currying): sum' = foldl (+) 0.
  • Build new lists with foldr and : (cheap); foldl with ++ is expensive. Anything that traverses a list once is probably a fold.
  • foldl1/foldr1: no start value (use first/last element); error on empty lists.
  • foldr f z [3,4,5,6] = f 3 (f 4 (f 5 (f 6 z))). foldl g z = g (g (g (g z 3) 4) 5) 6.
  • scanl/scanr/scanl1/scanr1 are folds that report every intermediate accumulator. scanl result is last; scanr result is first.
sum' = foldl (+) 0
elem' y ys = foldl (\acc x -> if x == y then True else acc) False ys
map' f xs = foldr (\x acc -> f x : acc) [] xs
maximum' = foldr1 (\x acc -> if x > acc then x else acc)
reverse' = foldl (\acc x -> x : acc) []        -- or foldl (flip (:)) []
product' = foldr1 (*)
filter' p = foldr (\x acc -> if p x then x : acc else acc) []
head' = foldr1 (\x _ -> x)
last' = foldl1 (\_ x -> x)
scanl (+) 0 [3,5,2,1]      -- [0,3,8,10,11]
scanr (+) 0 [3,5,2,1]      -- [11,8,3,1,0]
sqrtSums = length (takeWhile (<1000) (scanl1 (+) (map sqrt [1..]))) + 1   -- 131

Why foldr works on infinite lists but foldl does not

  • foldr f acc (x:xs) = f x (foldr f acc xs). By laziness, if f ignores its second argument the recursive call is never evaluated, so foldr can stop early.
  • foldl f acc (x:xs) = foldl f (f acc x) xs always recurses first, so on an infinite list it never stops, even after finding the answer.
  • f must be lazy in its right argument for foldr to terminate.
containsThree = foldr (\x rest -> if x == 3 then True else rest) False   -- works on [1..]
containsThreeFoldl = foldl (\acc x -> if x == 3 then True else acc) False  -- runs forever on [1..]
DoThink "what is the result for the empty list?" to choose the starting value. Use foldr for infinite lists and for building lists.
Don'tUse foldl1/foldr1 on possibly empty lists. Use foldl on an infinite list.

6.6 Function application with $

  • f $ x = f x: lowest precedence, right-associative (space application is highest, left-associative). Saves brackets: sum $ map sqrt [1..130], sqrt $ 3 + 4 + 9, f (g (z x)) = f $ g $ z x.
  • Also lets you treat application as a function: map ($ 3) [(4+), (10*), (^2), sqrt] = [7.0,30.0,9.0,1.7320508075688772].
DoUse $ to drop trailing brackets.

8.9 The Functor typeclass

  • class Functor f where fmap :: (a -> b) -> f a -> f b. Here f is a type constructor (takes one type), not a concrete type. map is just fmap for lists. Box-like types are functors: lists, Maybe, Tree, Either a, Map k.
  • For Either a only the Right is mapped (the Left is like an empty box with an error note). Instance heads: instance Functor Maybe, instance Functor (Either a).
  • Functors should obey laws: fmap id leaves the structure unchanged, and fmap shouldn't reorder (a wrong Tree instance could break the search-tree order). More in a later chapter.
class Functor f where
    fmap :: (a -> b) -> f a -> f b
instance Functor [] where
    fmap = map
instance Functor Maybe where
    fmap f (Just x) = Just (f x)
    fmap f Nothing = Nothing
instance Functor Tree where
    fmap f EmptyTree = EmptyTree
    fmap f (Node x leftsub rightsub) = Node (f x) (fmap f leftsub) (fmap f rightsub)
instance Functor (Either a) where
    fmap f (Right x) = Right (f x)
    fmap f (Left x) = Left x
DoWrite instance Functor Maybe (no parameter). Map only the part that changes (Right).
Don'tWrite instance Functor (Maybe m). Map the Left of Either a.

9.3 Files and streams

  • getContents :: IO String reads all of stdin lazily, only as needed (works well with unix pipes cat file | ./prog). Keep I/O small: read, apply a pure function, print.

  • readFile :: FilePath -> IO String (lazy; closed for you), writeFile (truncates), appendFile (adds; remember "\n" since getLine has no newline).

9.7 Exceptions

  • Prefer Maybe/Either in types for failure. Exceptions are for I/O (file missing, disk full). Pure code can throw too (4 div 0, head []), but those can only be caught in I/O code, and laziness makes timing unclear: don't mix exceptions and pure code.
  • Option 1: check first: doesFileExist :: FilePath -> IO Bool (System.Directory). Option 2: catch :: IO a -> (IOError -> IO a) -> IO a (System.IO.Error): `toTry catch handler`.

  • ioeGetFileName :: IOError -> Maybe FilePath extracts the file name. You can cover parts of main with different handlers. Often better: actions of type IO (Either a b).

    | otherwise = ioError e

10.1 Reverse Polish notation (RPN) calculator

  • Infix: 10 - (4 + 3) * 2. RPN: 10 4 3 + 2 * -: no brackets. By hand: go left to right with a stack. Number: push. Operator: pop two, apply, push the result. At the end one number remains.
  • Plan: words to split into items; left fold over them with the stack as accumulator (a list, top at the head because consing is fast); head of the final stack is the answer. Type: solveRPN :: (Num a, Read a) => String -> a (Read because we call read).
  • Patterns in the folding function are tried top to bottom: operators first, then a number string as the catch-all. Note - is y - x (x is the top). Easy to add operators (even non-binary: ln, sum). Not fault-tolerant (crashes on bad input); a Maybe Float version comes with monads (hint: reads).
solveRPN :: (Num a, Read a) => String -> a
solveRPN = head . foldl foldingFunction [] . words
    where   foldingFunction (x:y:ys) "*" = (x * y):ys
            foldingFunction (x:y:ys) "+" = (x + y):ys
            foldingFunction (x:y:ys) "-" = (y - x):ys
            foldingFunction xs numberString = read numberString:xs
-- extended version, type changed to Float
solveRPN :: String -> Float
solveRPN = head . foldl foldingFunction [] . words
    where   foldingFunction (x:y:ys) "*" = (x * y):ys
            foldingFunction (x:y:ys) "+" = (x + y):ys
            foldingFunction (x:y:ys) "-" = (y - x):ys
            foldingFunction (x:y:ys) "/" = (y / x):ys
            foldingFunction (x:y:ys) "^" = (y ** x):ys
            foldingFunction (x:xs) "ln" = log x:xs
            foldingFunction xs "sum" = [sum xs]
            foldingFunction xs numberString = read numberString:xs
ghci> solveRPN "10 4 3 + 2 * -"          -4
ghci> solveRPN "10 10 10 10 sum 4 /"     10.0
DoThink of the by-hand process: it often suggests a fold with a clear accumulator. Choose the representation that makes the common operation cheap (stack at the list head).
Don'tForget the Read a constraint when you use read. Swap the operands of - and / (it is y - x).

10.2 Heathrow to London

  • Two main roads A and B with crossing roads C; fixed time per part; find the fastest route. Input is read in threes (A, B, C), with a final crossing of 0.
  • By hand: for each pair of crossroads keep the best path to the next A and to the next B. Best to next A = min(forward from previous A, forward from previous B then cross over); same for B. At the end take the cheaper of the two paths.
  • Data: first idea (graph of Node/Road) works but a section is simpler: data Section = Section {getA, getB, getC :: Int}, type RoadSystem = [Section]. Use your own type rather than a tuple so the type system knows what's what (a vector vs a section). data Label = A | B | C, type Path = [(Label, Int)].
  • roadStep :: (Path, Path) -> Section -> (Path, Path) is the left-fold function. Paths are built by consing, so they are reversed: reverse at the end. The result has a harmless (C,0) at the end.
  • groupsOf n splits a list into groups; main reads input lazily, builds the road system, prints path and price. Optimisation: carry the prices along instead of summing each time. If stack overflow: use foldl'.
data Section = Section { getA :: Int, getB :: Int, getC :: Int } deriving (Show)
type RoadSystem = [Section]
heathrowToLondon :: RoadSystem
heathrowToLondon = [Section 50 10 30, Section 5 90 20, Section 40 2 25, Section 10 8 0]
data Label = A | B | C deriving (Show)
type Path = [(Label, Int)]
roadStep :: (Path, Path) -> Section -> (Path, Path)
roadStep (pathA, pathB) (Section a b c) =
    let priceA = sum $ map snd pathA
        priceB = sum $ map snd pathB
        forwardPriceToA = priceA + a
        crossPriceToA = priceB + b + c
        forwardPriceToB = priceB + b
        crossPriceToB = priceA + a + c
        newPathToA = if forwardPriceToA <= crossPriceToA
                        then (A,a):pathA
                        else (C,c):(B,b):pathB
        newPathToB = if forwardPriceToB <= crossPriceToB
                        then (B,b):pathB
                        else (C,c):(A,a):pathA
    in  (newPathToA, newPathToB)
optimalPath :: RoadSystem -> Path
optimalPath roadSystem =
    let (bestAPath, bestBPath) = foldl roadStep ([],[]) roadSystem
    in  if sum (map snd bestAPath) <= sum (map snd bestBPath)
            then reverse bestAPath
            else reverse bestBPath
groupsOf :: Int -> [a] -> [[a]]
groupsOf 0 _ = undefined
groupsOf _ [] = []
groupsOf n xs = take n xs : groupsOf n (drop n xs)
main = do
    contents <- getContents
    let threes = groupsOf 3 (map read $ lines contents)
        roadSystem = map (\[a,b,c] -> Section a b c) threes
        path = optimalPath roadSystem
        pathString = concat $ map (show . fst) path
        pathPrice = sum $ map snd path
    putStrLn $ "The best path to take is: " ++ pathString
    putStrLn $ "The price is: " ++ show pathPrice
-- cat paths.txt | runhaskell heathrow.hs   ->   BCACBBC, price 75

Don'tAppend with ++ in a loop (slow). Use an unlabelled tuple for something with its own meaning.

Haskell types connect to typeclasses by what they can act like, and typeclasses are open (you can add instances for your own types). This chapter covers three abstract behaviours: functors (mapped over), applicative functors (apply functions inside contexts) and monoids (combine with an identity).

11.1 Functors redux

  • fmap :: (a -> b) -> f a -> f b. The box analogy is okay but better: a functor is a computational context (may fail, may have many values...). Instances need kind * -> *: Either a, not Either.
  • IO is a functor: fmap f action = do { result <- action; return (f result) }. fmap reverse getLine is an action whose result is reversed. Use it instead of "bind then apply then rename".
  • Functions are functors: instance Functor ((->) r) and fmap = (.). fmap (*3) (+100) 1 = 303. A function can be seen as a box holding its eventual result.
  • Lifting: fmap :: (a -> b) -> (f a -> f b) turns a normal function into one working on functors. fmap (replicate 3) works on any functor (list, Maybe, Either).
  • Functor laws (not enforced by Haskell): 1) fmap id = id; 2) fmap (f . g) = fmap f . fmap g. Break one with a single counter-example: CMaybe (counter incremented by fmap) breaks law 1: fmap id (CJust 0 "haha") = CJust 1 "haha". If laws hold, fmap does only mapping.
instance Functor IO where
    fmap f action = do
        result <- action
        return (f result)
main = do line <- fmap (intersperse '-' . reverse . map toUpper) getLine
          putStrLn line                          -- "hello there" -> "E-R-E-H-T- -O-L-L-E-H"
instance Functor ((->) r) where
    fmap = (.)
ghci> fmap (*3) (+100) 1                  303
data CMaybe a = CNothing | CJust Int a deriving (Show)
instance Functor CMaybe where              -- NOT a real functor (breaks law 1)
    fmap f CNothing = CNothing
    fmap f (CJust counter x) = CJust (counter+1) (f x)
DoUse fmap instead of binding an I/O result only to transform it. Check both laws for your instances.
Don'tMake an instance that does extra work in fmap (counters, reordering).

11.2 Applicative functors

  • Problem: fmap (*) (Just 3) = Just (3*), a function inside a functor, and fmap can't apply it to Just 5. Control.Applicative: class (Functor f) => Applicative f where pure :: a -> f a; (<*>) :: f (a -> b) -> f a -> f b.
  • pure puts a value in a minimal context. <*> extracts a function from the left and maps it over the right (also sequences effects). Left-associative. pure f <*> x = fmap f x, so write f <$> x <*> y <*> z where <$> is infix fmap.
  • Maybe: pure = Just; Nothing <*> _ = Nothing; Just f <*> something = fmap f something. List: pure x = [x]; fs <*> xs = [f x | f <- fs, x <- xs] (all combinations; non-deterministic computations; a good replacement for comprehensions). IO: pure = return; a <*> b = do { f <- a; x <- b; return (f x) }. Functions: pure x = \_ -> x; f <*> g = \x -> f x (g x).
  • ZipList (newtype ZipList a = ZipList {getZipList :: [a]}): zips instead of all combinations; pure x = ZipList (repeat x); use getZipList to print. One type can't have two instances of one class, hence the wrapper. Replaces zipWith3..zipWith7.
  • liftA2 f a b = f <$> a <*> b promotes a binary function to functors. sequenceA :: Applicative f => [f a] -> f [a] (recursion or foldr (liftA2 (:)) (pure [])): Maybe: Nothing if any is Nothing; functions: feed one input to a list of functions; lists: all combinations; IO: same as sequence.
  • Applicative laws: pure f <*> x = fmap f x; pure id <*> v = v; pure (.) <*> u <*> v <*> w = u <*> (v <*> w); pure f <*> pure x = pure (f x); u <*> pure y = pure ($ y) <*> u.

(++) <$> Just "johntra" <*> Just "volta"        -- Just "johntravolta"

(+) <$> (+3) <*> (*100) $ 5                     -- 508
getZipList $ (+) <$> ZipList [1,2,3] <*> ZipList [100,100,100]       -- [101,102,103]

DoUse f <$> x <*> y to apply an ordinary function to several wrapped values. Use sequenceA to turn a list of Maybes into a Maybe list.
Don'tWrite pure f <*> x when f <$> x is clearer. Put functions of different types in one list.

11.3 The newtype keyword

  • newtype ZipList a = ZipList { getZipList :: [a] }: wraps an existing type as a new type. Faster than data (wrapper is removed at run time) but only one constructor with one field. Can derive instances (the wrapped type needs them).
  • Use it to give a type a second instance (e.g. a tuple's Functor on the first component): newtype Pair b a = Pair { getPair :: (a,b) } with instance Functor (Pair c). Pattern matching on a newtype is a conversion, not unboxing.
  • Laziness: with newtype, helloMe (CoolBool _) = "hello" works on undefined; with data, it throws (Haskell must look at the constructor). newtype is lazier.
  • type vs newtype vs data: type = new name for an existing type, interchangeable (IntList = [Int]); newtype = new, separate type wrapping an existing one, mainly to make instances; data = completely new types with any number of constructors and fields.
newtype CharList = CharList { getCharList :: [Char] } deriving (Eq, Show)
newtype Pair b a = Pair { getPair :: (a,b) }
instance Functor (Pair c) where
    fmap f (Pair (x,y)) = Pair (f x, y)
ghci> getPair $ fmap (*100) (Pair (2,3))     (200,3)
newtype CoolBool = CoolBool { getCoolBool :: Bool }
helloMe (CoolBool _) = "hello"               -- helloMe undefined = "hello" (with data: exception)
type IntList = [Int]
DoUse newtype when you write a data with one constructor and one field. Use type just for readable signatures.
Don'tExpect newtype to inherit instances or accept ++ on the wrapped list. Use newtype with two constructors.

11.4 Monoids

  • A monoid = an associative binary function plus an identity value for it: * with 1; ++ with []. Properties: takes two values of the same type, returns that type, identity exists, and grouping order doesn't matter (associativity: (3*4)*5 = 3*(4*5); - is not associative).
  • class Monoid m where mempty :: m; (<>) :: m -> m -> m; mconcat :: [m] -> m (default foldr (<>) mempty). Instances are concrete types. <> (old name mappend) is just a binary function, not necessarily "appending". Laws: mempty <> x = x, x <> mempty = x, (x <> y) <> z = x <> (y <> z). a <> b = b <> a is not required (lists: "one" <> "two" differs).
  • Lists: mempty = [], <> = ++; mconcat = concat. Product/Sum (Data.Monoid): * and 1 / + and 0; wrapped, use getProduct, getSum. Any/All: || and False / && and True.
  • Ordering: mempty = EQ; LT <> _ = LT; EQ <> y = y; GT <> _ = GT: compare by several criteria in priority order (like dictionary order). Not commutative.
  • Maybe a: if a is a monoid: mempty = Nothing, Just m1 <> Just m2 = Just (m1 <> m2). For any a: First keeps the first Just, Last the last Just.
  • Foldable (Data.Foldable, import qualified as F): things that can be folded; F.foldr works on any foldable (Maybe, trees). Implement foldMap :: (Monoid m, Foldable t) => (a -> m) -> t a -> m and you get foldr/foldl free. For a tree: mempty for Empty; for a node foldMap f l <> f x <> foldMap f r. foldMap also reduces to one monoid value (Any, lists).
class Monoid m where
    mempty :: m
    (<>) :: m -> m -> m
    mconcat :: [m] -> m
    mconcat = foldr (<>) mempty
instance Monoid [a] where
    mempty = []
    (<>) = (++)
getProduct . mconcat . map Product $ [3,4,2]    -- 24
getSum . mconcat . map Sum $ [1,2,3]             -- 6
getAny . mconcat . map Any $ [False, False, False, True]   -- True
instance Monoid Ordering where
    mempty = EQ
    LT <> _ = LT
    EQ <> y = y
    GT <> _ = GT
lengthCompare :: String -> String -> Ordering
lengthCompare x y = (length x `compare` length y) <>
                    (vowels x `compare` vowels y) <>
                    (x `compare` y)
    where vowels = length . filter (`elem` "aeiou")
getFirst . mconcat . map First $ [Nothing, Just 9, Just 10]    -- Just 9
instance F.Foldable Tree where
    foldMap f Empty = mempty
    foldMap f (Node x l r) = F.foldMap f l <> f x <> F.foldMap f r
getAny $ F.foldMap (\x -> Any $ x == 3) testTree     -- True
F.foldMap (\x -> [x]) testTree                         -- [1,3,6,5,8,9,10]

12.1 Getting our feet wet with Maybe

  • Maybe a = a value with a context of possible failure. For Maybe bind keeps the context: Nothing stays Nothing; Just x applies the function to x. First written as applyMaybe.
  • Applicatives can't make one step depend on the previous result; monads can.
applyMaybe :: Maybe a -> (a -> Maybe b) -> Maybe b
applyMaybe Nothing f  = Nothing
applyMaybe (Just x) f = f x
Just 3 `applyMaybe` \x -> Just (x+1)                                 -- Just 4
Just 1 `applyMaybe` \x -> if x > 2 then Just x else Nothing          -- Nothing

12.2 The Monad type class

  • class Applicative m => Monad m where return :: a -> m a (default pure); (>>=) :: m a -> (a -> m b) -> m b; (>>) :: m a -> m b -> m b; x >> y = x >>= \_ -> y. A monad instance needs an Applicative instance first. return is just pure (and not like imperative return).
  • Maybe instance: Nothing >>= f = Nothing; Just x >>= f = f x. Just 9 >>= \x -> return (x*10) = Just 90. You get the value without pattern matching and still keep the context.
class Applicative m => Monad m where
    return :: a -> m a
    return = pure
    (>>=) :: m a -> (a -> m b) -> m b
    (>>) :: m a -> m b -> m b
    x >> y = x >>= \_ -> y
instance Monad Maybe where
    Nothing >>= f = Nothing
    Just x >>= f  = f x

12.3 Walk the line (Pierre and the birds)

  • Model: type Birds = Int, type Pole = (Birds,Birds). Pierre falls if the sides differ by 4 or more. Without failure, landLeft/landRight chain easily (-: helps readability: x -: f = f x) but can't detect a temporary fall.
  • Add failure with Maybe Pole (guards). Now use >>= to chain: return (0,0) >>= landLeft 1 >>= landRight 4 >>= landLeft (-1) >>= landRight (-2) = Nothing. Failure propagates automatically; this beats nested case expressions.
  • >>: m >> n = m >>= \_ -> n ignores the value but keeps the context: Nothing >> Just 3 = Nothing; Just 3 >> Just 4 = Just 4. banana _ = Nothing or >> Nothing makes Pierre fall.
landLeft :: Birds -> Pole -> Maybe Pole
landLeft n (left,right)
    | abs ((left + n) - right) < 4 = Just (left + n, right)
    | otherwise                    = Nothing
landRight :: Birds -> Pole -> Maybe Pole
landRight n (left,right)
    | abs (left - (right + n)) < 4 = Just (left, right + n)
    | otherwise                    = Nothing
ghci> return (0,0) >>= landRight 2 >>= landLeft 2 >>= landRight 2     Just (2,4)
ghci> return (0,0) >>= landLeft 1 >> Nothing >>= landRight 1          Nothing
-- without the monad: nested cases
routine = case landLeft 1 (0,0) of
    Nothing -> Nothing
    Just pole1 -> case landRight 4 pole1 of
        Nothing -> Nothing
        Just pole2 -> landLeft 2 pole2
DoTurn functions that can fail into a -> Maybe b and chain them with >>=.
Don'tUse only applicative style when each step depends on the previous result. Write nested case towers.

12.4 do notation

  • do works for any monad: it is syntax for chaining >>= with lambdas. Each line is a monadic value; x <- m binds the result; the last line can't be bound and is the result of the whole block. A line without <- is like >>. If any value is Nothing, the whole thing is Nothing.
  • Pattern matching works on the left of <-. If it fails, fail (from MonadFail) is called: for Maybe it gives Nothing instead of crashing (wopwop = do (x:xs) <- Just ""; return x = Nothing).
  • Choose >>= when each step uses just the previous result; do when it reads better.
foo :: Maybe String
foo = Just 3   >>= (\x ->
      Just "!" >>= (\y ->
      Just (show x ++ y)))
foo = do
    x <- Just 3
    y <- Just "!"
    Just (show x ++ y)
routine :: Maybe Pole
routine = do
    start <- return (0,0)
    first <- landLeft 2 start
    second <- landRight 2 first
    landLeft 1 second              -- Just (3,2)
routine = do
    start <- return (0,0)
    first <- landLeft 2 start
    Nothing                        -- banana peel: same as _ <- Nothing
    second <- landRight 2 first
    landLeft 1 second
justH = do
    (x:xs) <- Just "hello"
    return x                       -- Just 'h'
class Monad m => MonadFail m where
    fail :: String -> m a
instance MonadFail Maybe where
    fail _ = Nothing
DoBind with <-; end with the result expression. Use pattern matching on <- when failure should become Nothing.
Don'tTry to bind the last line. Think do is only for I/O or only imperative.

12.5 The list monad

  • Context = non-determinism. xs >>= f = concat (map f xs); return x = [x]. [3,4,5] >>= \x -> [x,-x] = [3,-3,4,-4,5,-5]. Failure is the empty list (like Nothing): [1,2,3] >>= \x -> [] = [].
  • do with lists: each <- takes every value. List comprehensions are syntactic sugar for the list monad.
  • Alternative (Control.Applicative): empty :: f a and (<|>) :: f a -> f a -> f a (for lists [] and ++). guard :: Alternative f => Bool -> f (): guard True = pure (), guard False = empty. In the list monad guard filters: it is the comprehension predicate.
instance Monad [] where
    xs >>= f = concat (map f xs)

12.7 Monad laws

  • Being an instance of Monad doesn't make it a monad: the laws must hold (Haskell can't check them).
  • Left identity: return x >>= f = f x. Right identity: m >>= return = m. Associativity: (m >>= f) >>= g = m >>= (\x -> f x >>= g) (nesting doesn't matter).
  • Composition of monadic functions: f <=< g = \x -> g x >>= f. Laws become: f <=< return = f; return <=< f = f; f <=< (g <=< h) = (f <=< g) <=< h, like id and . for normal functions.
return 3 >>= (\x -> Just (x+100000))        -- Just 100003, same as (\x -> Just (x+100000)) 3
[1,2,3,4] >>= (\x -> return x)               -- [1,2,3,4]
(<=<) :: (Monad m) => (b -> m c) -> (a -> m b) -> (a -> m c)
f <=< g = (\x -> g x >>= f)
let f x = [x,-x]; g x = [x*3,x*2]; h = f <=< g in h 3     -- [9,-9,6,-6]
DoCheck the three laws for any monad you define.
Don'tMake a Monad instance where return does extra effects (failing or adding results).

13.1 Writer

  • Writer = a value with another value attached that acts like a log; logs are combined automatically. First try: isBigGang :: Int -> (Bool, String). To feed a value with a log into such a function, applyLog keeps the old log and appends the new one.
  • The log needn't be a String or a list: any monoid works (<> instead of ++), e.g. a price as Sum Int. applyLog :: (Monoid m) => (a,m) -> (a -> (b,m)) -> (b,m).
  • newtype Writer w a = Writer { runWriter :: (a, w) } (from Control.Monad.Writer). return x = Writer (x, mempty) (identity monoid, so nothing is added); >>= runs f and combines logs with <>. No Show instance: use runWriter. No fail (pattern failure calls error).
  • do notation: all attached monoid values are <>ed. tell adds a log entry (result ()); the last line must be return (...) or you lose the result.
  • Inefficiency: lists as logs are fast when ++ associates right (a ++ (b ++ (c ++ d))) but slow when it associates left (((a ++ b) ++ c) ++ d), e.g. logging in reverse (gcdReverse).
  • Difference lists: a list represented as a function that prepends it: \xs -> [1,2,3] ++ xs. Append = function composition (f . g), so it is always efficient. Wrap: newtype DiffList a = DiffList { getDiffList :: [a] -> [a] }; toDiffList xs = DiffList (xs++); fromDiffList (DiffList f) = f []; monoid: mempty = DiffList (\xs -> [] ++ xs), f <> g = DiffList (\xs -> f (g xs)). finalCountDown 500000 is quick with DiffList, very slow with normal lists.
applyLog :: (Monoid m) => (a,m) -> (a -> (b,m)) -> (b,m)
applyLog (x,log) f = let (y,newLog) = f x in (y,log <> newLog)
type Food = String
type Price = Sum Int
addDrink :: Food -> (Food,Price)
addDrink "beans" = ("milk", Sum 25)
addDrink "jerky" = ("whiskey", Sum 99)
addDrink _ = ("beer", Sum 30)
ghci> ("dogmeat", Sum 5) `applyLog` addDrink `applyLog` addDrink      ("beer",Sum {getSum = 65})
newtype Writer w a = Writer { runWriter :: (a, w) }
instance (Monoid w) => Monad (Writer w) where
    return x = Writer (x, mempty)
    (Writer (x,v)) >>= f = let (Writer (y, v')) = f x in Writer (y, v <> v')
logNumber :: Int -> Writer [String] Int
logNumber x = Writer (x, ["Got number: " ++ show x])

    a <- logNumber 3
    b <- logNumber 5
    tell ["Gonna multiply these two"]
    return (a*b)                 -- (15,["Got number: 3","Got number: 5","Gonna multiply these two"])
gcd' :: Int -> Int -> Writer [String] Int
gcd' a b
    | b == 0 = do
        tell ["Finished with " ++ show a]
        return a
    | otherwise = do
        tell [show a ++ " mod " ++ show b ++ " = " ++ show (a `mod` b)]
        gcd' b (a `mod` b)

13.2 Reader (functions as monads)

  • (->) r is a monad: the context is that the value isn't there yet; you must apply the function to something. return x = \_ -> x; h >>= f = \w -> f (h w) w. Also called the reader monad: all functions "read" from one common argument.
instance Monad ((->) r) where
    return x = \_ -> x
    h >>= f = \w -> f (h w) w
addStuff :: Int -> Int
addStuff = do
    a <- (*2)
    b <- (+10)
    return (a+b)               -- addStuff 3 = 19, same as (+) <$> (*2) <*> (+10)
addStuff x = let a = (*2) x
                 b = (+10) x
             in a+b

13.3 State

  • Stateful computation = s -> (a, s): take a state, give a result and a new state (pure, no mutation). Context: you must supply an initial state, and you get a new one back. Avoids threading generators by hand (threeCoins).
  • Stack example: pop :: Stack -> (Int, Stack), push :: Int -> Stack -> ((), Stack); gluing them manually is tedious.
  • newtype State s a = State { runState :: s -> (a,s) } (Control.Monad.State). return x = State $ \s -> (x,s) (state unchanged). >>=: run h on s, apply f to the result, run the new computation on the new state. Type: State s a -> (a -> State s b) -> State s b: the state type s must stay the same, the result can change.

13.5 Useful monadic functions

  • liftM :: Monad m => (a -> b) -> m a -> m b = fmap using only >>=/return: liftM f m = m >>= (\x -> return (f x)). ap :: Monad m => m (a -> b) -> m a -> m b = <*>. So monads are stronger than applicatives and functors; often write the Monad instance first, then pure = return, <*> = ap, fmap = liftM. liftA2/liftM2..5 apply a function between 2-5 values.
  • join :: Monad m => m (m a) -> m a flattens nested monadic values (join (Just (Just 9)) = Just 9; lists: concat; Writer: logs combined, outer first). m >>= f = join (fmap f m): handy when making your own instance (flatten is often easier than bind).
  • filterM :: Monad m => (a -> m Bool) -> [a] -> m [a]: filter with a monadic predicate (e.g. Writer logs). Powerset: powerset xs = filterM (\x -> [True, False]) xs.
  • foldM :: Monad m => (a -> b -> m a) -> a -> [b] -> m a: monadic left fold (e.g. fail if a number > 9).
  • Safe RPN: readMaybe st = case reads st of [(x,"")] -> Just x; _ -> Nothing; folding function returns Maybe [Double]; solveRPN st = do [result] <- foldM foldingFunction [] (words st); return result (the pattern fails to Nothing unless exactly one item remains).
  • Composing monadic functions: foldr (.) id [f,g,h] for normal functions; foldr (<=<) return for monadic ones: inMany x start = return start >>= foldr (<=<) return (replicate x moveKnight); canReachIn x start end = end elem inMany x start.

    x <- m
    return (f x)
join :: (Monad m) => m (m a) -> m a

    m <- mm
    m

13.6 Making monads (probabilities)

  • Idea: lists with a probability on each item: [(3,1%2),(5,1%4),(9,1%4)], using Rational (Data.Ratio, written 1%4, exact, no float error). Wrap: newtype Prob a = Prob { getProb :: [(a,Rational)] } deriving Show.
  • Functor: map values, keep probabilities. Monad: return x = Prob [(x,1%1)] (certain); m >>= f = flatten (fmap f m), where flatten multiplies inner probabilities by the outer one. Probabilities should sum to 1. Laws hold because the list monad is the basis and multiplication is associative.
  • Use: two fair coins and a loaded coin (9/10 tails): all tails = 9 % 40. The monad doesn't merge equal outcomes (exercise).
import Data.Ratio
newtype Prob a = Prob { getProb :: [(a,Rational)] } deriving Show
instance Functor Prob where
    fmap f (Prob xs) = Prob $ map (\(x,p) -> (f x,p)) xs
flatten :: Prob (Prob a) -> Prob a
flatten (Prob xs) = Prob $ concat $ map multAll xs
    where multAll (Prob innerxs,p) = map (\(x,r) -> (x,p*r)) innerxs
instance Monad Prob where
    return x = Prob [(x,1%1)]
    m >>= f = flatten (fmap f m)
    fail _ = Prob []
data Coin = Heads | Tails deriving (Show, Eq)
coin :: Prob Coin
coin = Prob [(Heads,1%2),(Tails,1%2)]
loadedCoin :: Prob Coin
loadedCoin = Prob [(Heads,1%10),(Tails,9%10)]
flipThree :: Prob Bool
flipThree = do
    a <- coin
    b <- coin
    c <- loadedCoin
    return (all (==Tails) [a,b,c])

14.1 Taking a walk

  • Seed type: data Tree a = Empty | Node a (Tree a) (Tree a) deriving (Show). Changing one element by nested pattern matching (changeToP) is ugly. Better: pass a list of Directions (L or R) as a focus; an empty list focuses on the whole tree.
  • Inefficient for repeated edits: each time you walk from the root again.
data Direction = L | R deriving (Show)
type Directions = [Direction]
changeToP :: Directions -> Tree Char -> Tree Char
changeToP (L:ds) (Node x l r) = Node x (changeToP ds l) r
changeToP (R:ds) (Node x l r) = Node x l (changeToP ds r)
changeToP [] (Node _ l r) = Node 'P' l r
elemAt :: Directions -> Tree a -> a
elemAt (L:ds) (Node _ l _) = elemAt ds l
elemAt (R:ds) (Node _ _ r) = elemAt ds r
elemAt [] (Node x _ _) = x

ghci> elemAt [R,L] newTree          'P'

14.2 A trail of breadcrumbs

  • Walk one step at a time and leave breadcrumbs. First try: breadcrumbs = list of directions (reversed): goLeft (Node _ l _, bs) = (l, L:bs). Not enough to go back up.
  • A breadcrumb must contain everything needed to rebuild the parent node: the direction taken, the parent's element and the subtree not taken (but not the focused subtree). data Crumb a = LeftCrumb a (Tree a) | RightCrumb a (Tree a); type Breadcrumbs a = [Crumb a]. Like a node with a hole in it.
  • goUp rebuilds the parent from the latest crumb. A pair of the focused tree and the breadcrumbs is a zipper: type Zipper a = (Tree a, Breadcrumbs a). -: (x -: f = f x) makes walking readable. goLeft on Empty or goUp at the top errors (fixed in 14.5).
  • modify f changes the focused root (leaves Empty alone); attach t replaces the focus with a tree (extend a leaf or replace a subtree); topMost goes up until no crumbs remain.
x -: f = f x
data Crumb a = LeftCrumb a (Tree a) | RightCrumb a (Tree a) deriving (Show)
type Breadcrumbs a = [Crumb a]
type Zipper a = (Tree a, Breadcrumbs a)
goLeft :: Zipper a -> Zipper a
goLeft (Node x l r, bs) = (l, LeftCrumb x r:bs)
goRight :: Zipper a -> Zipper a
goRight (Node x l r, bs) = (r, RightCrumb x l:bs)
goUp :: Zipper a -> Zipper a
goUp (t, LeftCrumb x r:bs) = (Node x t r, bs)
goUp (t, RightCrumb x l:bs) = (Node x l t, bs)
modify :: (a -> a) -> Zipper a -> Zipper a
modify f (Node x l r, bs) = (Node (f x) l r, bs)
modify f (Empty, bs) = (Empty, bs)
attach :: Tree a -> Zipper a -> Zipper a
attach t (_, bs) = (t, bs)
topMost :: Zipper a -> Zipper a
topMost (t,[]) = (t,[])
topMost z = topMost (goUp z)

14.4 A very simple file system

  • data FSItem = File Name Data | Folder Name [FSItem] with type Name = String, type Data = String. A crumb is like a folder missing the chosen item: data FSCrumb = FSCrumb Name [FSItem] [FSItem] (name, items before, items after, so the hole's position is known). No crumb for files (can't go deeper). type FSZipper = (FSItem, [FSCrumb]).
  • fsUp rebuilds the folder from the latest crumb. fsTo name uses break (nameIs name) to split the folder items around the one named; errors if the name is missing or the focus is a file. Manipulate: fsRename, fsNewFile.
  • Because data is immutable, you also get versioning for free: the old file system (myDisk) and the new one both still exist.
type Name = String
type Data = String
data FSItem = File Name Data | Folder Name [FSItem] deriving (Show)
data FSCrumb = FSCrumb Name [FSItem] [FSItem] deriving (Show)
type FSZipper = (FSItem, [FSCrumb])
fsUp :: FSZipper -> FSZipper
fsUp (item, FSCrumb name ls rs:bs) = (Folder name (ls ++ [item] ++ rs), bs)
fsTo :: Name -> FSZipper -> FSZipper
fsTo name (Folder folderName items, bs) =
    let (ls, item:rs) = break (nameIs name) items
    in  (item, FSCrumb folderName ls rs:bs)
nameIs :: Name -> FSItem -> Bool
nameIs name (Folder folderName _) = name == folderName
nameIs name (File fileName _) = name == fileName
fsRename :: Name -> FSZipper -> FSZipper
fsRename newName (Folder name items, bs) = (Folder newName items, bs)
fsRename newName (File name dat, bs) = (File newName dat, bs)
fsNewFile :: FSItem -> FSZipper -> FSZipper
fsNewFile item (Folder folderName items, bs) = (Folder folderName (item:items), bs)
let newFocus = (myDisk,[]) -: fsTo "pics" -: fsNewFile (File "heh.jpg" "lol") -: fsUp
DoKeep the items before and after in the crumb so you can rebuild in order.
Don'tCall fsTo for a name that isn't in the folder or while focusing on a file (crash).
